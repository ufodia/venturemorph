# Brand and naming

## Ground the identity

Derive audience, category, benefit, proof, promise, and character from the actual project and chosen route. Distinguish intended positioning from customer perception. A new feature does not automatically require a new name.

Compare what the brand invites users to expect with current delivery. Resolve unsupported claims through product improvement or narrower language before extending them into marketing.

## Evaluate the current name

| Dimension | Practical check |
| --- | --- |
| Expectation | What category, audience, or benefit might a prospective user infer? |
| Distinctiveness | Can users distinguish it from relevant alternatives? |
| Spoken use | Can the target audience pronounce, hear, spell, and search it? |
| Associations | What meanings appear in relevant languages and contexts? |
| Memory | Can users recall it after exposure, beyond immediate recognition? |
| Expansion | Does it support the credible next direction? |
| Existing equity | What recognition, referrals, search history, and trust could a change risk? |
| Availability | What domain, account, marketplace, or trademark checks were actually performed? |

Use reasons and evidence, or mark unknown. Interpretation and pronunciation guesses are hypotheses until checked with relevant speakers/users.

## Choose a proportionate verdict

If no name has been selected, use **Not applicable: name not selected** and develop positioning/character or requested name candidates. If an existing name was not supplied, say its fit is unassessed and ask only if it is needed for the requested decision. Do not invent a name to make a verdict possible.

- **Keep:** Identity supports the direction; make targeted execution fixes.
- **Evolve:** A descriptor, promise, message, tone, or behavior update can resolve the mismatch.
- **Rename:** Material confusion or limiting associations are evidenced, and a smaller change is unlikely to resolve them. Account for recognition loss, migration, discoverability, redirects, accounts, and communication.

Give a provisional verdict and specific test if evidence is insufficient. Transition cost matters but does not automatically justify keeping a harmful name. Comprehension and delayed recall tests answer different questions; neither establishes legal clearance.

When generating names, derive three to five candidates from distinct strategic directions. Explain meaning, spoken use, fit, expansion, associations, and weaknesses. Include the existing name as a comparator where relevant.

Report availability per candidate/source as verified available, verified unavailable, or unverified, with time and scope. No search result is not proof of availability. A registrar result is not trademark clearance; a free handle is not a domain registration. Do not buy or reserve anything without authorization.

## Make character observable

Choose a few traits grounded in the audience and promise. Define behavior at difficult moments. For a calm, user-controlled product:

| Touchpoint | Do | Avoid |
| --- | --- | --- |
| Onboarding | State first value; let users choose pace. | Manufactured urgency. |
| Notifications | Give timing controls and a useful reason. | Guilt unrelated to value. |
| Errors | Explain failure and the available action. | Humor that obscures failure. |
| Pricing | Explain cost and changes before payment. | Surprise restrictions. |
| Sharing | Give preview and control. | Claiming privacy while exposing activity. |

Adapt to the project rather than imposing this personality universally. Make conflicts between growth mechanics and character explicit.
